# SSL / TLS Certificates

Production TLS for `dendreo.competences-et-metiers.com` (and the
`netdata.` subdomain) is a Let's Encrypt certificate, served by the
`dendreo_nginx_prod` container from a bind-mount.

## How it works

- **Files nginx expects:** `ssl/fullchain.pem` and `ssl/privkey.pem`
  (NOT `cert.pem`/`key.pem`). See [`nginx/prod.conf`](../nginx/prod.conf).
- On the VPS these live at `/opt/dendreo/ssl/`, bind-mounted read-only into the
  container at `/etc/nginx/ssl/` (see `docker-compose.prod.yml`).
- Certs are git-ignored (`*.pem`) — never commit them.

## Automated renewal (current setup)

Renewal is fully automated on the VPS — **no GitHub Actions, no manual step:**

1. The `certbot.timer` systemd unit runs `certbot renew` twice daily.
2. Renewal uses the **ACME HTTP-01 webroot** challenge: certbot writes challenge
   files to `/opt/dendreo/certbot-webroot`, which nginx serves on port 80 via
   the `location /.well-known/acme-challenge/` blocks in `nginx/prod.conf`.
   nginx keeps running — **zero downtime.**
3. On a successful renewal, the certbot **deploy-hook**
   `/etc/letsencrypt/renewal-hooks/deploy/dendreo-nginx.sh` copies the fresh
   cert into `/opt/dendreo/ssl/` and hot-reloads nginx (`nginx -s reload`).

The deploy-hook and timer are installed by the Ansible `app` role
([`infra/ansible/roles/app/tasks/main.yml`](../infra/ansible/roles/app/tasks/main.yml),
template `templates/certbot-deploy-hook.sh.j2`).

## One-time setup on the VPS

Do this **once** to switch the existing cert (originally issued with the
`standalone` plugin) over to the automated webroot flow.

```bash
# 1. Deploy the nginx config + compose change that add the ACME webroot.
#    From your workstation (infra/ansible), or on the box, run the app role so
#    /opt/dendreo/nginx/*.conf and the webroot dir are updated, then recreate
#    nginx so it serves /.well-known/acme-challenge/ and mounts the webroot:
cd /opt/dendreo
docker compose -f docker-compose.prod.yml up -d nginx

# 2. Confirm the challenge path is reachable over plain HTTP:
mkdir -p /opt/dendreo/certbot-webroot
echo ok | sudo tee /opt/dendreo/certbot-webroot/healthz >/dev/null
curl -s http://dendreo.competences-et-metiers.com/.well-known/acme-challenge/healthz   # -> ok
sudo rm /opt/dendreo/certbot-webroot/healthz

# 3. Re-issue the cert with the webroot authenticator (updates the renewal
#    config from standalone -> webroot). No downtime. Keep both SANs:
sudo certbot certonly --webroot -w /opt/dendreo/certbot-webroot \
  -d dendreo.competences-et-metiers.com \
  -d netdata.dendreo.competences-et-metiers.com \
  --cert-name dendreo.competences-et-metiers.com --keep-until-expiring

# 4. Install the deploy-hook + enable the timer (or just run the Ansible app role):
#    cd infra/ansible && ansible-playbook playbooks/setup.yml

# 5. Verify the whole renewal path end-to-end (does NOT touch the live cert):
sudo certbot renew --dry-run
```

Only after `certbot renew --dry-run` succeeds is the automation proven. The old
stopgap workflow (`.github/workflows/renew-cert-temp.yml`) has been removed; if
you ever need a manual break-glass renewal you can restore it from git history.

## Bootstrap from scratch (no cert yet)

If `/opt/dendreo/ssl/` is empty, nginx boots on a self-signed placeholder
(generated by the Ansible `app` role) so port 443 answers. Then run steps 1–5
above but use plain `certonly --webroot ...` (drop `--keep-until-expiring`) to
issue the first real cert.

## Manual issuance / renewal (fallback)

```bash
# Renew now and publish via the deploy-hook:
sudo certbot renew --force-renewal

# Inspect current cert + expiry:
sudo certbot certificates
echo | openssl s_client -connect localhost:443 \
  -servername dendreo.competences-et-metiers.com 2>/dev/null \
  | openssl x509 -noout -enddate
```

## Security notes

- Never commit `*.pem` to version control.
- Port 80 must stay open (ACME HTTP-01 challenge + HTTP→HTTPS redirect) — it is,
  via the Scaleway security group in `infra/terraform/main.tf`.
- The cert covers both the apex app host and the `netdata.` subdomain as SANs;
  keep both `-d` flags on any manual reissue.
